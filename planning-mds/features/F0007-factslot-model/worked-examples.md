# F0007 worked examples and boundaries

**Provenance:** Synthetic development examples, kept outside the frozen holdout. The outputs below are expected results for the F0007 slot identity and answer contracts (v0.1A), not observed runtime results. The later feature action must reproduce them through the service and PostgreSQL.

Definitions are in the [glossary](../../domain/glossary.md#factslot) and [ADR-0077](../../architecture/decisions/ADR-0077-factslot-identity-and-typed-answer-carriers.md). [contract-examples.json](contract-examples.json) holds 26 structured cases, each with a local schema path and its expected validity. Schema validity does not establish resolution, authorization or persistence behaviour.

| Example | Worked expectation | Boundary / failure | Story and contract |
|---|---|---|---|
| EX-SLOT-001: qualified limits (ADR-0006, EX-GL-001) | `test:hasLimitAmount@v1` with `{basis: EachOccurrence, currency: USD}` on coverage subject E resolves to slot S1. Changing only the basis to `GeneralAggregate` gives S2. Sending `{currency, basis}` in the reverse order, or a decimal qualifier written as `1E+6` instead of `1000000.00`, resolves S1 again. | Two concurrent resolvers both receive S1 and there is one qualifier set. A forced fingerprint collision yields `FINGERPRINT_COLLISION` and the slots are not merged. `basis: null` yields `QUALIFIER_NULL_REJECTED`; it is never treated as omitted. | S0001 AC1–AC4; fact-slot-key-v1, resolution-result-v1 |
| EX-SLOT-002: same question, two KBs (ADR-0061, ADR-0066 §1a) | Tenant entity E is associated with KB A and KB B. The same key resolves to S1 in KB A and S3 in KB B. | A KB-B-only principal is denied resolution and reads of S1. The response is the facade's not-found and reveals no difference between "denied" and "no such slot". | S0001 AC5, S0005 AC4 |
| EX-SLOT-003: two additional insureds (§109.1) | `test:hasAdditionalInsured@v1` is MULTI with members keyed by entity. Insured X and insured Y become members M1 and M2 under header H. Resolving X again returns M1. Versions for M1 and M2 overlap in time without tripping the exclusion. | Closing M1 references no M2 row; F0008 proves the temporal close. A commit addressed to H is `MULTI_SLOT_REQUIRES_MEMBER`. A SINGLE limit slot still rejects overlapping versions (ADR-0008 regression). | S0002 AC2, AC3, AC5 |
| EX-SLOT-004: relationship object | A RELATIONSHIP slot (subject E, predicate P, object O1) is distinct from (E, P, O2). | An object that is not associated with the slot's KB yields `RELATIONSHIP_OBJECT_OUT_OF_SCOPE`. A RELATIONSHIP predicate with no object yields `RELATIONSHIP_OBJECT_REQUIRED`. | S0002 AC4, AC6 |
| EX-OWN-003: three kinds of no value | Three commits through `POST /facts/{id}/commits` to three identity-v1 slots, each reloaded: (1) `NOT_PROCESSED` for the slot that was never read; (2) `NOT_FOUND`, scope = artifact A, profile `gl-policy-profile/1`, pages 1–3; (3) `NOT_STATED` with its reviewed scope. All three reload with their scopes intact. | A `NOT_FOUND` with no scope, or with an empty page list, is `ABSENCE_SCOPE_REQUIRED`. A value attached to `EXPLICIT_NEGATIVE` is `STATE_VALUE_MISMATCH`. A principal who cannot read artifact A gets the non-disclosing denial, never page numbers. No `ACCESS_DENIED` state exists. | S0003 AC1–AC6; fact-answer-v1 |
| EX-MONEY-001: exact amounts | `1000000`, `1000000.00` and `1E+6` USD are stored as `"1000000"` and compare equal. `0.01`, `999999999999999.99` and `9007199254740993` round-trip exactly. | A JSON number amount is `MONEY_FLOAT_REJECTED`. `US$` is `CURRENCY_INVALID`. A limit without its basis is `BASIS_REQUIRED`. A value carrying `converted_from` is `CONVERTED_MONEY_UNSUPPORTED`. | S0004 AC1–AC3, AC6 |
| EX-ID-001: scoped identifiers | `GL-1001` issued by carrier A (`carrier:<A>`) and `GL-1001` issued by carrier B are different identifiers and different MULTI members. FEIN `12-3456789` and `123456789` under `us-irs` normalize to `123456789` and are equal. | An identifier with no scheme is `IDENTIFIER_SCHEME_REQUIRED`. No normalization makes values from different schemes equal. | S0004 AC4, AC5 |
| EX-SEM-008: rename keeps the entity | "Acme Roofing Inc." and, after the endorsement, "Acme Roofing & Restoration Inc." are two versions in the same `sys:hasLegalName@v1` slot for entity E. No new entity or slot is created. | A name with no admitted F0006 v2 assertion in the same tenant/KB is `NAME_EVIDENCE_REQUIRED`. Resolving `sys:hasLegalName@v1` as MULTI is `CARDINALITY_CONFLICT`. F0008/F0019 split the valid time. | S0005 AC1–AC3 |
| EX-NAME-002: display hook | The hook returns E's current accepted name facts in KB A: legal, trade and known-as, each with its kind and slot, ordered by predicate key, then normalized form, then slot ID. | The order is not a precedence rule (open decision for F0017/F0023). No `entity_alias` row is written. Names known only in KB A never appear for KB B. | S0005 AC4, AC5 |
| EX-PILOT-001: legacy slot | The fixture slot `each_occurrence_limit` from `seed_fact_slot` keeps NULL identity columns, its `slot_type` and its unwrapped values. GET and commit behave exactly as before 0012. | Updating that row to add a predicate key is rejected by trigger. No qualifier is created for it. Downgrade refuses while any identity-v1 row exists. | S0006 AC1–AC6 |

The full 39-AC runtime matrix is in [feature-assembly-plan.md](feature-assembly-plan.md). The structured cases cover contract shape only. PostgreSQL concurrency, ownership keys, authorization and migration behaviour are claimed only by the feature run.

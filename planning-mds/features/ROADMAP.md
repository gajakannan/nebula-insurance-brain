## Purpose

- Provide a current planning dashboard for sequencing decisions.

- Avoid constant churn in `BLUEPRINT.md`, which stays baseline strategy.

## Update Rules

- Update whenever feature priority or sequence changes, by editing the feature shard and recompiling.
- Keep entries at feature level (not story-level unless explicitly needed).
- Every feature carries a rationale for its section.

## Governed retrieval planning sequence

The [2026-11-06 design amendment](../architecture/governed-evidence-retrieval-design.md) uses the existing Now/Next/Later prioritization: baseline retrieval remains v0.2A; the read-only F0067 consumer remains v0.2B; F0068 is a conditional v0.4+ experiment. Confidence in spectral benefit is unestablished until measured; no release is accelerated by this incorporation.

F0035 Phase A can clarify the downstream problem first. F0033/F0034 projection/checkpoint contracts must settle before F0035 Phase B approval; production adapters precede F0035 integration, and F0036 binds its generation interface afterward. QE/PM plan fixtures and an executable runner before implementation measurements. The baseline can close without spectral work. F0068 needs a separate experiment scope/scheduling/cost decision after baseline results; F0061 retains its existing scope. Features remain Planned and keep their own plan actions and approvals.

# Feature Security Review Report

Feature: F0005 — One-time Docling ingestion (run `2026-10-25-4020923b`, gate G3)

Reviewer: Security Reviewer (independent session; not an author of the code or the evidence). Date: 2026-10-26.
Product: `nebula-insurance-brain`, branch `feature/f0005-live-qualification` , uncommitted worktree. HEAD is `3d99ceb`. The review covers `git diff` plus the untracked files.
Scope: local Docker Compose and development host only. This is the ADR-0060 acceptance scope: a trusted operator CLI, a synthetic qualification corpus, and a dedicated loopback vLLM. The review does not qualify production, non-synthetic documents or ADR-0060 acceptance.

Result: PASS WITH RECOMMENDATIONS

## Summary
- Assessment: PASS WITH RECOMMENDATIONS
- Findings: Critical 0, High 0, Medium 1, Low 3. These are new findings from F0005. Pre-existing F0004 items are noted separately and are not counted.
- What holds:
  - Credential handling holds. The host guard is fail-closed. The converter child receives no inherited guard descriptor and no credentials in its environment.
  - Authorization is re-checked on every attempt, so revocation is honored.
  - Job-history reason codes are constrained to an enumeration.
  - No environment variable selects a pipeline, and the guard-directory override is rejected.
  - Migration 0009 is expand-only, and its downgrade refuses to destroy history.
- What is left:
  - The converter child's isolation only strips the environment. It is not privilege separation.
  - That child parses PDFs with a dependency stack that carries 76 open advisories.
  - This is not exploitable in the current synthetic scope. It must be fixed before any activation, or before any non-synthetic document is processed (SEC-F5-M1).

### Medium

**SEC-F5-M1: the converter child is isolated only by its environment, while it parses untrusted PDFs with an advisory-laden stack**
- Location:
  - Child environment: `neuron/packages/brain-ingestion/src/brain_ingestion/conversion_process.py:50-64` (`_CHILD_ENV` passes `HOME`) and `:346-349`.
  - Child spawn: `:413-440` (same UID, no rlimits, no network or filesystem confinement).
  - Exec of the recorded provider command line during quiesce: `provider_supervisor.py:112-122` .
  - Locked parser dependencies: `neuron/uv.lock` (unchanged from HEAD).
- What:
  - The child runs as the worker's OS account and inherits `HOME`. It has full filesystem access as that account, including:
    - `~/.brain-secrets` ;
    - the content store;
    - `/tmp/nebula-brain-inference-<uid>/` , including `<key>.provider.json` .
  - "No inference or publication capability" holds at the API and environment level: `_NoInferenceClient`, `pass_fds` limited to two pipes, a stripped environment, and parent-only publication. It does not hold at the OS level.
  - The child has no memory limit. The 300 s deadline bounds CPU and time, but not memory.
- Why it matters / exploit scenario:
  - The F0004 threat model treats the document supplier as untrusted even when a trusted operator submits the document. Several advisories are reachable on the PDF path:
    - pypdf 6.19.0: 11 advisories. Infinite-loop, long-runtime and memory-exhaustion issues are reachable through `PdfReader(...).pages` and `extract_text()` (`docling_adapter.py` `_count_pages_needing_ocr`, plus the new empty-page count). Both run inside the child.
    - pillow 12.3.0: 37 advisories, 27 of them memory-corruption or write class. Examples: the bundled libopenjp2 heap overflow GHSA-78g4-xqwv-q3g8, the FPX RCE GHSA-5x8w-8jj5-q52h, and TIFF/JPEG encoder overflows.
  - Pillow reachability is **not demonstrated**:
    - Docling's PDF backend renders pages through pypdfium2 and docling-parse. Pillow then processes the rendered bitmaps rather than decoding attacker-chosen image formats.
    - I treat Pillow RCE as unproven and pypdf DoS as reachable.
  - The chained impact if any converter-stage code execution occurs:
    - The child can read the inference credential from `~/.brain-secrets` .
    - It can rewrite `provider.json` `argv`. The next `provider_supervisor quiesce` then `Popen`s that command line with the operator's environment, including `BRAIN_INFERENCE_API_KEY` and `VLLM_API_KEY`. That gives a persistent foothold that survives the child's process-group kill.
  - Without code execution, a crafted PDF can exhaust host memory. On this development host the OOM killer can then take the co-resident GPU server.
- Why it is not exploitable now:
  - The corpus is synthetic, generated by `neuron/fixtures/qualification/build_corpus.py` with reportlab, and hash-pinned in `CORPUS-HASHES.txt` .
  - Submission is a trusted-operator CLI. There is no HTTP upload route; the engine API diff is empty.
  - The committed config stays on `direct-baseline` with `v2_writer_enabled: false`.
- Remediation, required **before any activation, and before any non-synthetic or externally supplied document is processed by this worker**:
  - (a) Run the converter child under a separate unprivileged UID or a container/namespace. Give it no access to `$HOME`, the control directory or the content store: read-only except its staging directory, no network, and `HF_HUB_OFFLINE=1` forced. Apply `RLIMIT_AS`/`RLIMIT_NOFILE` or a cgroup memory cap. And/or:
  - (b) Upgrade the parser stack and requalify. pypdf ≥ 6.21.2 is independent of the measured pins and can be done as a follow-up. Pillow ≥ 13.0.0 is blocked by `docling-core`/`docling-parse` requiring `pillow<13`, so it needs a Docling upgrade (≥ 2.132.0 also clears the docling and docling-slim records). That changes measured pins and requires re-running S0001/S0005 provenance and the qualification comparison.
  - Also bind the provider record to something the child cannot forge: verify the restart `argv` against an operator-owned allowlist (see SEC-F5-L1).
- Owner: AI Engineer + DevOps. Target: activation precondition. Not required to close this feature on the rejection branch. Track as an F0005 follow-up or an F0026 security-baseline item.

### Low

**SEC-F5-L1: the supervisor trusts the provider record for kill and exec without cross-checking it at use time**
- Location:
  - `worker_guard.py:355-367` (`ProviderRecord.capture` accepts any PID).
  - `provider_supervisor.py:78-92` (`confirm_stopped`).
  - `provider_supervisor.py:53-75` and `:112-132` (restart and readiness).
  - `provider_supervisor.py:112` (provider log opened with the default umask).
- What:
  - `record --pid` does not check that `pid == pgid`, that the `argv` is a `vllm serve`, or that the PID owns the listening socket for the canonical endpoint.
  - `confirm_stopped` checks the leader's start ticks. It never verifies that `os.getpgid(record.pid) == record.pgid` before `killpg(record.pgid)`.
  - `quiesce` restarts with the supervisor's inherited environment. `wait_ready` accepts a server that does not enforce authentication: it only sends the bearer token and never checks that an unauthenticated request is refused.
- Exploit scenario:
  - Operator error or a same-UID tamper (see M1) can cause a kill of the wrong process group or an exec of the wrong command. For example, `pgrep -f` can match a `bash -c` wrapper that contains the pattern, which records the wrapper shell's group.
  - Running `quiesce` without `VLLM_API_KEY` exported silently restarts an unauthenticated loopback provider, and the run still reports ready.
- Not presently exploited: I checked the live state.
  - The recorded provider has `pid == pgid` and a `vllm serve` `argv` with no `--api-key`.
  - The control directory is `0700` and owned by `gajap`.
  - The restarted server returns `401` to an unauthenticated `/v1/models` request and listens on `127.0.0.1:8000` only.
- Remediation:
  - At record time, require `pid == pgid`, the `vllm serve` argv shape, no credential flags, and socket ownership.
  - At kill time, re-check `getpgid(pid) == pgid` when the leader is alive.
  - In `wait_ready`, assert that `/v1/models` without credentials returns 401/403.
  - Pass an explicit minimal environment to the restart.
  - Open the provider log `0600`.
- Owner: DevOps. Target: follow-up before activation.

**SEC-F5-L2: the live-qualification settings object prints the inference credential in its repr**
- Location: `neuron/benchmarks/f0005_qualification.py:225-238` (`LiveSettings`, a `@dataclass` with `api_key: str`). It is used by `neuron/tests/integration/f0005_live_support.py:43` and the live tests.
- What: any repr of `LiveSettings` contains the key. This includes `pytest -l`/`--showlocals`, a debugger, a `print`, or the repr of an exception argument.
- Evidence:
  - My probe in the scratchpad (`g3probe/test_repr_probe.py` , with a sentinel value) confirms that pytest's default and `-vv` assertion output did not print it.
  - `-l` did print it.
  - A run-folder-wide search found no `LiveSettings(` or `api_key=` text. `commands.log` holds only variable references; the line-93 diagnostic script prints booleans, not the value.
  - No leak has occurred.
- Exploit scenario: a future failing live lane run with `-l` writes the key into a committed live lane log such as `artifacts/test-results/live-provider-storage-auth-faults.log` .
- Remediation: `api_key: str = field(repr=False)`, or wrap it in a secret type. Recommended before any further live lane run.
- Owner: AI Engineer.

**SEC-F5-L3: free-form `--pipelines` is interpolated into the schema DDL in the benchmark (the semgrep `avoid-sqlalchemy-text` results)**
- Location: `neuron/benchmarks/f0005_qualification.py:143-147` (`CREATE SCHEMA "{schema}"`), `:208` (`DROP SCHEMA "{schema}" CASCADE`) and `:642-644` (`--pipelines` has no `choices`).
- What:
  - The QE manifest summary says the identifier comes from a "fixed pipeline name". In fact `--pipelines` accepts any string, and it reaches the DDL before any pipeline validation.
  - A `"` in the value breaks out of the quoted identifier.
- Impact: test-only, an operator-supplied argument, and run against the operator's own `BRAIN_TEST_POSTGRES_URL`. The only risk is self-injection, for example `DROP SCHEMA` of an unintended schema through a typo or a pasted value. The benchmark is not packaged or reachable from production composition.
- Remediation: `choices=EXTRACTION_PIPELINES`, or validate against `^[a-z-]+$` before building the schema name. Correct the manifest summary wording.
- Owner: AI Engineer. Target: follow-up.

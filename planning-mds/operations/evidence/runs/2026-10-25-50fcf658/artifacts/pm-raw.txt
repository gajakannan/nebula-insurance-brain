## Story Header

**Story ID:** F0005-S0001

**Feature:** F0005 — One-time document ingestion

**Title:** Pin and process source documents

**Priority:** High

**Phase:** MVP — v0.1A

**Status:** In Progress

## User Story

**As a** document intelligence engineer

**I want** the pinned Docling-Graph pipeline to convert real native, scanned and mixed-page sources and publish them before any model call

**So that** conversion is proven on the actual parser and OCR stack, not only on synthetic native content.

## Context & Background

Implements the [PRD](PRD.md) under proposed [ADR-0060](../../architecture/decisions/ADR-0060-docling-graph-document-pipeline-orchestration.md). Delivered 2026-09-20: the 1.9.1 pin, wheel digest, lock, checkpoint stage and synthetic conversion tests ([compatibility evidence](compatibility-evidence.md)). This plan adds live conversion of the qualification corpus. F0004's v1/v2 publication boundary is the checkpoint target.

## Acceptance Criteria

- [ ] **F0005-S0001-AC1:** Given a clean checkout, when both workspaces sync from their locks, then the resolved Docling-Graph, Docling and docling-core versions and the Graph wheel digest equal the recorded pin, and any difference fails the qualification run before conversion.
- [ ] **F0005-S0001-AC2:** Given each native, scanned and mixed-page corpus document, when it enters the real pipeline with physical conversion and OCR enabled, then the published bundle records parser name/version/configuration, OCR engine name/version, page count, failed pages, OCR page count, warnings and source hash; mocks or recorded native JSON cannot satisfy this criterion.
- [ ] **F0005-S0001-AC3:** Given conversion completes and the model endpoint then fails or returns invalid output, when the checkpoint stage runs, then the bundle is verified and registered before the first model request, and the job records the model failure without discarding or reconverting the bundle.
- [ ] **F0005-S0001-AC4:** Given the corpus's partial-conversion document, when conversion returns, then supported content is published with its failed pages and partial status, and no later stage labels the document complete.
- [ ] **F0005-S0001-AC5:** Given the checkpoint callback fails or the installed stage layout differs from the pinned guard, when processing is attempted, then extraction does not start, the job fails with an explicit integration reason, and no artifact is registered ready.
- [ ] **F0005-S0001-AC6:** Given a job, artifact or run state change, when the operation succeeds or fails, then an audit event records actor and job identity, correlation and attempt IDs, artifact/run references, outcome and timestamp, without secrets or source text.

**Edge Cases & Error Scenarios:** Encrypted or corrupt PDF → explicit conversion failure with no bundle. OCR model assets missing offline → conversion fails before publication; no fallback to an unrecorded engine. A page that converts empty is a failed page, not silent success.

## Interaction Contract

No UI. Entry point: the worker CLI `submit` command and the worker loop under a provisioned ServicePrincipal.

| Surface / Entry Point | User Action | Editable State | Save / Mutation Result | Reload / Persistence Evidence | Roles / Status Constraints |
|---|---|---|---|---|---|
| Worker CLI submission → conversion → checkpoint publication | Submit a corpus PDF | New job only; published bundle immutable | Verified bundle registered ready, or explicit conversion/integration failure | Restart, reload the artifact through the authorized reader, compare hashes and identities | ServicePrincipal with current `ingest` grant in the target tenant/KB |

**Validation and audit:** a failed conversion or checkpoint never registers a ready artifact; every authorization decision and state change is audited with policy version.

## Data Requirements

Source/version, tenant/KB, native document and file hashes, parser and OCR identities, parse quality, attempts and outcomes; F0004 manifest contract version. Exact OCR model-asset identity is qualified in S0005.

## Role-Based Visibility

Only principals and jobs with current `ingest` authorization read source or bundle bytes; each decision is audited with its policy version. Model calls receive authorized content only, never credentials or authorization data.

## Non-Functional Expectations

- Conversion of each corpus document completes within 300 s on the development host, or fails explicitly at that bound.
- Source text and secrets stay out of routine logs.

## Dependencies

F0004 publication boundary and verifier; F0001 fixtures and inference runbook; ADR-0060.

## Out of Scope

New parser or OCR engines, non-PDF formats, production host deployment.

## Questions & Assumptions

The installed pin is not upgraded by this plan. If live conversion forces an upgrade, the checkpoint seam and every S0001–S0003 criterion are re-proven on the new pin.

## Definition of Done

- [ ] Every acceptance criterion has observed live evidence on the pinned package.
- [ ] Applicable runtime tests, authorization checks and contract validation pass.
- [ ] STATUS, compatibility evidence and trackers describe the actual implementation.
- [ ] Required reviewer verdicts are recorded in STATUS; planning checks are not runtime proof.

## Story Header

**Story ID:** F0005-S0002

**Feature:** F0005 — One-time document ingestion

**Title:** Persist artifacts and recover jobs

**Priority:** High

**Phase:** MVP — v0.1A

**Status:** In Progress

## User Story

**As a** platform engineer

**I want** document jobs to recover from live provider, storage and process failures without reconverting or duplicating effects

**So that** retries preserve published evidence and never produce two accepted results.

## Context & Background

Implements the [PRD](PRD.md) under proposed [ADR-0060](../../architecture/decisions/ADR-0060-docling-graph-document-pipeline-orchestration.md). Delivered 2026-09-21: the PostgreSQL queue (migration 0004) and nine database recovery cases with recorded model responses. Not yet proven: live-provider failures, storage write failures, and recovery through the F0004 publication boundary.

## Acceptance Criteria

- [ ] **F0005-S0002-AC1:** Given a published bundle, when the live vLLM endpoint is stopped, times out, returns HTTP 5xx, returns malformed JSON or returns schema-invalid output, then the attempt fails with a distinct recorded reason, finite retries resume from the saved native JSON, and converter/OCR call counters stay at zero after publication.
- [ ] **F0005-S0002-AC2:** Given a worker process killed after bundle publication, after result publication, mid-import and after import commit, when a new worker claims the job, then it completes with exactly one accepted artifact, one run per profile, one assertion/evidence/review set and one acknowledged completion.
- [ ] **F0005-S0002-AC3:** Given a storage write failure or crash before the manifest completion marker, when recovery runs, then the incomplete publication is never exposed as ready, is cleaned or resumed under the F0004 store contract, and the job reconverts at most once.
- [ ] **F0005-S0002-AC4:** Given duplicate submissions, competing workers, expired leases or cancellation during model calls, when jobs execute, then stale attempts are fenced, cancellation stops further model scheduling within one in-flight call, and the configured model concurrency limit (default 1 for the host GPU) is never exceeded, including Graph-internal fan-out.
- [ ] **F0005-S0002-AC5:** Given a different tenant, a revoked grant or an inactive principal, when a job or reader accesses source, bundle, run output or temporary export, then access is denied and audited; the job does not continue under stale authority.
- [ ] **F0005-S0002-AC6:** Given run outputs, chunks, provenance ledgers and temporary exports holding source text, when a run completes, fails or is cancelled, then temporary files are removed and retained outputs sit under the owning tenant/KB scope with the same retention as the source.
- [ ] **F0005-S0002-AC7:** Given a job, artifact or run state change, when the operation succeeds or fails, then an audit event records actor and job identity, correlation and attempt IDs, artifact/run references, outcome and timestamp, without secrets or source text.

**Edge Cases & Error Scenarios:** Retry budget exhausted → job ends `failed` with the bundle retained and readable. Provider recovers mid-retry → no duplicate assertion set. Disk full during result publication → result not registered; bundle untouched.

## Interaction Contract

No UI. Entry points: worker loop, importer and the CLI `cancel` command; failures are injected by the qualification harness.

| Surface / Entry Point | User Action | Editable State | Save / Mutation Result | Reload / Persistence Evidence | Roles / Status Constraints |
|---|---|---|---|---|---|
| Worker/importer under injected failure | Submit, kill, cancel or resubmit a job | Job state transitions only; accepted artifacts and results immutable | One accepted outcome per scoped version, recipe and profile, or an explicit terminal failure | Database row counts, counters and audit history after restart | ServicePrincipal `ingest`/`interpret` grants; revocation takes effect at the next boundary |

**Validation and audit:** every terminal failure carries a reason code; no failure path records a successful mutation.

## Data Requirements

Job, attempt, lease generation, idempotency key, failure reason, counters (conversion, OCR, model calls), artifact and run references, retention scope.

## Role-Based Visibility

Run outputs and temporary exports require the same current authorization as the source, rechecked after every restart; operators read failure reasons, not source text, from logs.

## Non-Functional Expectations

- Recovery after a worker kill completes within one lease period plus one attempt.
- Queue depth beyond the configured bound rejects new submissions explicitly rather than growing without limit.

## Dependencies

S0001 checkpoint; F0004 store contract and v1 fallback; F0002/F0003 authorization and persistence; ADR-0059.

## Out of Scope

Multi-host deployment, distributed GPU quotas, Temporal workflows (F0050), retention-period policy changes.

## Questions & Assumptions

PostgreSQL durable jobs and outbox stay the v0.1 mechanism. Failure before publication may reconvert once; failure after publication may not.

## Definition of Done

- [ ] Every acceptance criterion has observed evidence with the live provider and real storage.
- [ ] Applicable runtime tests, authorization checks and contract validation pass.
- [ ] STATUS, compatibility evidence and trackers describe the actual implementation.
- [ ] Required reviewer verdicts are recorded in STATUS; planning checks are not runtime proof.

## Story Header

**Story ID:** F0005-S0004

**Feature:** F0005 — One-time document ingestion

**Title:** Evaluate and activate the proven pipeline

**Priority:** High

**Phase:** MVP — v0.1A

**Status:** In Progress

## User Story

**As a** platform owner

**I want** a measured direct-versus-Graph comparison against agreed thresholds, followed by activation or rejection

**So that** Graph replaces the direct client only on evidence, and either outcome is recorded and reversible.

## Context & Background

Implements the [PRD](PRD.md) under proposed [ADR-0060](../../architecture/decisions/ADR-0060-docling-graph-document-pipeline-orchestration.md). Delivered 2026-09-22: a recorded-response [synthetic comparison](synthetic-comparison.json), which is orchestration proof, not model quality. This plan adds the live corpus comparison, reviewer verdicts and the activation decision.

## Acceptance Criteria

- [ ] **F0005-S0004-AC1:** Given the qualification corpus (at least 12 synthetic documents: 6 native, 4 scanned, 2 mixed-page), when it is committed, then every expected value and evidence location was authored from the document source by a role that does not run or review the extraction, and the corpus and expectation hashes are recorded before the first measured run.
- [ ] **F0005-S0004-AC2:** Given the direct baseline and Graph dense under recorded configurations (pins, model and tokenizer revision, chunking, budgets), when both profiles run over the full corpus, then the report records per-case and aggregate schema validity, field accuracy, abstention, fabricated evidence, evidence resolution, calls, serving-tokenizer tokens, p95 latency and review items per document.
- [ ] **F0005-S0004-AC3:** Given the report, when it is compared with the PRD thresholds, then each threshold is marked met or missed with its measured value; a missed threshold blocks activation and is never re-run with relaxed budgets to pass.
- [ ] **F0005-S0004-AC4:** Given S0001–S0003 and S0005 evidence plus the report, when QA, Architect and Security review them, then each records a verdict with evidence references in STATUS, and the operator records acceptance or rejection.
- [ ] **F0005-S0004-AC5:** Given all thresholds met, every verdict passing and operator acceptance, when activation runs, then ADR-0060 becomes Accepted, the worker default extraction contract becomes Graph dense through committed non-secret configuration, the v2 writer is enabled per S0005, and the dependency matrix, build/run metadata and C4 runtime description are updated together.
- [ ] **F0005-S0004-AC6:** Given an activated configuration, when the rollback setting selects the direct baseline, then new runs use the direct client with its own identity, existing artifacts and runs stay readable and unchanged, and no run mixes engines.
- [ ] **F0005-S0004-AC7:** Given any threshold miss, failing verdict or operator rejection, when the feature closes, then the direct client stays default, the v2 writer stays disabled, ADR-0060 records the failed gates (Proposed or Rejected per operator), and no partial activation remains.
- [ ] **F0005-S0004-AC8:** Given a job, artifact, run or activation state change, when the operation succeeds or fails, then an audit event records actor and job identity, correlation and attempt IDs, artifact/run references, outcome and timestamp, without secrets or source text.

**Edge Cases & Error Scenarios:** Live model unavailable during measurement → the run is void and repeated in full, never partially merged. Baseline worse than Graph on every metric → still reported; the baseline remains the rollback path. Reviewer finds an expectation error → the corrected expectation is re-hashed and both engines are re-measured.

## Interaction Contract

No UI. Entry points: the comparison harness, the committed configuration file and the ADR/STATUS records.

| Surface / Entry Point | User Action | Editable State | Save / Mutation Result | Reload / Persistence Evidence | Roles / Status Constraints |
|---|---|---|---|---|---|
| Comparison harness → report | Run both engines over the corpus | Report immutable once recorded; a re-run creates a new report | Hashed report with per-case rows | Re-run reproduction command; compare corpus and configuration hashes | QA owns corpus; AI engineer runs; reviewers do not author expectations |
| Committed configuration | Activate or roll back | Default extraction contract and `content.v2_writer_enabled` | Next job uses the selected engine and writer | Restart worker; submit a document; inspect run and manifest identity | Activation only after AC4 acceptance |

**Validation and audit:** activation and rollback are recorded in STATUS and the feature evidence package with the operator's decision.

## Data Requirements

Corpus manifest and hashes, expectation files, run configurations, per-case results, aggregate metrics, verdicts, activation decision and configuration diff.

## Role-Based Visibility

Corpus and reports are synthetic and repository-committed; measured runs execute under the ServicePrincipal's current authorization like any job, and activation needs no new permission; reports exclude secrets and serving credentials.

## Non-Functional Expectations

Thresholds as listed in the PRD. Measurement uses one worker replica and the model semaphore at 1.

## Dependencies

S0001–S0003, S0005; agent-role QA, Architect and Security reviewers; operator acceptance; F0026 reuses the cases.

## Out of Scope

Production host activation, licensed or frozen-holdout corpora, retiring the direct client code (it stays as the rollback path).

## Questions & Assumptions

Thresholds are the operator-approved PRD defaults. Graph direct is reported for completeness but is not an activation candidate.

## Definition of Done

- [ ] Every acceptance criterion has observed evidence.
- [ ] Applicable runtime tests, authorization checks and contract validation pass.
- [ ] STATUS, ADR-0060, dependency matrix and trackers describe the actual outcome.
- [ ] Required reviewer verdicts and the operator decision are recorded; planning checks are not runtime proof.

Implementation signoff belongs in [STATUS.md](STATUS.md). This planning update is not runtime completion or reviewer approval.

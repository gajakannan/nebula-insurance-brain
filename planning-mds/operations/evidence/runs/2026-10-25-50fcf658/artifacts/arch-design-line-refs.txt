planning-mds/features/F0005-one-time-docling-ingestion/feature-assembly-plan.md:76:**In-flight requests after timeout or worker death.** Releasing an OS lock does not cancel GPU work. Before dispatching each HTTP request, while holding the guard and semaphore, atomically write and fsync `<key>.inflight.json` plus its directory. It contains an opaque request/attempt correlation hash and provider-instance fingerprint, never prompt text or credentials. If durability fails, send nothing. Clear and fsync it only after a terminal provider response proves the request finished; an HTTP timeout, disconnected transport, cancellation without confirmed completion or process crash leaves it dirty. No next request is sent while dirty. Once the client has an uncertain outcome, stop claiming jobs; record the ordinary job failure (`model_timeout`, `model_unavailable` or `cancelled` as applicable) without assuming the provider stopped.

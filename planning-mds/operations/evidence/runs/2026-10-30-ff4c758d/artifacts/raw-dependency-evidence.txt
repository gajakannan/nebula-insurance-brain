34: ### Artifact checkpoint and reuse
35:
36: The ingestion operation coordinates conversion through Docling-Graph and publishes a complete, hashed native DoclingDocument plus normalized bundle before fallible semantic extraction proceeds. A retry after this checkpoint loads the saved native JSON. Profile changes create new interpretation runs over that bundle; they never submit the original PDF or a Markdown export as a substitute for the native JSON reuse path.
37:
38: F0005 implements and tests a version-pinned checkpoint stage immediately before upstream extraction, with a stage-layout guard. This is a Nebula integration seam, not an upstream durability guarantee. The inspected upstream orchestrator runs extraction before its optional export stages, and API mode does not dump artifacts by default. A single `run_pipeline()` call with an output directory is therefore insufficient evidence of crash-safe parse reuse. Dependency upgrades must revalidate the seam and publication ordering; do not silently relax the invariant or reach into unpinned internals.
39:
40: There is one accepted artifact per scoped document version and parser configuration. A crash before durable publication may require a conversion retry; after publication, downstream failures must never repeat conversion or OCR. Record attempts separately from accepted artifacts. Nebula owns leases, heartbeats, cancellation, idempotent publication, and job/outbox recovery under section 114.1; upstream in-process stage execution does not supply those guarantees.
41:
42: ### Extraction, provenance, and authority
43:
44: - F0015 compiles versioned Nebula profiles to trusted Pydantic templates and explicit pipeline configuration. Templates are application-controlled; user profile fields cannot select arbitrary Python imports. The compiler retains Nebula's ontology annotations, qualifiers, units, and schema hash.
45: - F0016 records the artifact hash, profile/template and schema hashes, pipeline revision/configuration, model/prompt identity, selected blocks, attempt, token usage, and outcome. Extraction graph, provenance ledger, and effective configuration are immutable run outputs, stored separately from the content bundle. Reinterpretation never mutates the parse artifact.
46: - F0005 proves a mapping from upstream chunks and native item references into Nebula block/table locators. A node identifier's text match does not ground every property or relationship. Preserve upstream precision and merge/derived lineage; unresolved or document-level grounding cannot become a fabricated span. ADR-0058 continues to govern evidence resolution and review.
47: - Upstream graph IDs and deduplication are local to extraction. F0017 owns tenant-scoped enterprise identity; F0018 owns canonical commits. Graph exports cannot write directly to canonical tables or the AGE projection. Assertions and relationship candidates enter the existing review and commit path.
48: - Keep the self-hosted vLLM policy from ADR-0055. Enforce input plus schema/prompt plus output token budgets before every model call, including repair, fill, and reconciliation calls. Revalidate the 4,096-token profile; upstream templates do not establish model adequacy. Keep source-bearing exports access-controlled and outside routine logs.

52: The candidate `DoclingGraphPipelineAdapter` in `brain-extraction` owns calls into the upstream package. `brain-ingestion` supplies the conversion checkpoint callback and keeps `build_bundle()` / `ContentArtifactStore` publication. The adapter provides the native document and parse quality (status, failed pages, OCR counts, warnings) to the callback before semantic extraction, through the tested, pinned stage integration. The callback finishes publication before processing continues. 56: ### Local control design amendments — Phase B approved 2026-10-25; implemented in F0005, now governed by ADR-0074
57:
58: The [assembly plan Steps 0a and 2](../../features/archive/F0005-one-time-docling-ingestion/feature-assembly-plan.md) place physical conversion in a supervised conversion-only process group. The parent starts a monotonic 300-second deadline before launch, durably records child ownership before acknowledging conversion start, and alone accepts the validated native-JSON/quality/provenance handoff and publishes ready through the existing current-authority/generation fence. The child runs the same pinned Graph conversion/stage guard, with a serialization callback and no inference/publication capability. Timeout latches failure at 300 seconds before bounded termination/cleanup; late results cannot publish or start extraction. This replaces the prior design's reliance on the model client's cooperative deadline; it does not weaken parse-once, checkpoint ordering or F0004's bundle contract.
59:
60: The local processing topology is one host-enforced worker per canonical dedicated serving endpoint, with a process-lifetime OS advisory lock in a fixed shared host control directory and a common in-process model semaphore of one. Aliases, model profiles, tenants, workspaces and temporary configs cannot allocate separate locks. The converter never inherits the descriptor. A durable in-flight marker precedes HTTP dispatch; ambiguous outcomes and SIGKILL keep replacement claims/requests stopped until the controlled-host harness/DevOps supervisor observes the dedicated provider group exit and restarts the pinned server under the same guard. Provider health alone is not quiescence. This fail-closed local recovery is measured against the existing recovery bound and is not a distributed quota or a new provider endpoint.
61:
62: Steps 6–7 explicitly start ordinary new jobs on `direct-baseline` with the v2 writer disabled. Isolated qualification configs select Graph direct/dense without changing that default. Rejection verifies/restores direct-baseline/v1 after restart; acceptance selects Graph dense/v2. Extraction rollback after acceptance selects direct while retaining the qualified v2 writer. New job idempotency includes the pipeline; historical jobs retain their existing keys/pinned meaning. Negative tests cover every branch, deadline races, child/orphan cleanup and competing-worker/provider-crash recovery before activation. None of these proposed controls changes this ADR's status or approves runtime activation.

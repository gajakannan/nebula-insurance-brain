    55	## Gotchas
    56	
    57	- **The fingerprint is not the identity.** Always compare the stored qualifier rows on conflict. Never treat a matching hash as proof of equality, and never merge slots on a collision.
    58	- **Release reference is not identity.** Recording a new `predicate_release_ref` on resolution of an existing slot must not create a new slot or update the old one, because identity columns are immutable by trigger.
    59	- **Members are slots.** Commit to the member slot ID, never to the MULTI header. This keeps the ADR-0008 exclusion per member without touching `canonical_fact_version`, which F0008 owns.
    60	- **Member values retain their identity.** PRESENT answers must canonicalize to the stored member key. A different entity, name or identifier is `MEMBER_VALUE_MISMATCH` and creates no commit/version/outbox rows; resolve a different member instead.
    61	- **Legacy rows stay legacy.** A NULL `identity_version` marks a pilot slot. Do not backfill predicate keys or qualifiers. Any later mapping must be explicit and reversible (F0012/F0013).
    62	- **Authorization comes first.** Run the resolver as the `operation` of `AuthorizationExecution.mutate` over the source artifacts with `INTERPRET`. Add the scope artifact and name-evidence source to `commit_source_keys` so denial precedes any reason code.
    63	- **Money amounts are strings.** Pydantic must not coerce a JSON number into a decimal string. Reject it (`MONEY_FLOAT_REJECTED`) before any model conversion.
    64	- **Decimal normalization is closed and bounded.** Input and canonical output use at most 64 total characters, including sign/point. The canonical length is checked before exponent expansion; oversized forms reject `DECIMAL_INVALID` rather than allocating padding.
    65	- **Scope-dependent reads are one protected operation.** Authorize the actual privately loaded answer and its scope in one current-authority unit of work, audit and commit once, then return. A separate precheck cannot authorize a later answer.
    66	- **`subject_kb_entity_id` is a generated column.** Never write it. It exists so the subject-KB foreign key ignores legacy rows (MATCH SIMPLE).
    67	- **Entity references that leave the KB.** An entity reference in a qualifier, a MULTI member or an answer value that is not associated with the slot's KB is rejected with `RELATIONSHIP_OBJECT_OUT_OF_SCOPE`, the same reason as an out-of-KB relationship object.
    68	- **The name hook authorizes per slot.** `AuthorizedFactSlots.current_names` runs `fact_slot:read` on each candidate slot. A slot the reader cannot read is absent, exactly like a missing one.
    69	- **The backup inventory hashes present columns only.** `scripts/ops/verify_content.py` reads the columns that exist at the database's revision, so backups of databases older than 0012 still work.

   348	   - stop resolver callers;
   349	   - identity-v1 slots and versions stay readable by the deployed binary, and no binary without the answer policy may commit to them;

## Overview and Scope

This plan implements six stories and 39 acceptance criteria. The design is recorded in Proposed [ADR-0077](../../../architecture/decisions/ADR-0077-factslot-identity-and-typed-answer-carriers.md), and this file is an implementation specification, not evidence of delivered code.

1. Real-PostgreSQL concurrent resolution yields one slot with one qualifier set, and the forced-collision fixture rejects without merging.
2. Two members of a MULTI slot carry independent versions without tripping the exclusion, and SINGLE overlap is still rejected.
3. Every carrier and value rejection writes zero rows, and EX-OWN-003 reloads as three distinct answers.
4. Cross-tenant/KB child, subject, object and scope negatives are rejected by the database or the facade with no disclosure.
5. Pilot slots and versions are byte-equal after upgrade, downgrade and upgrade again, and existing commit, review and assertion suites pass unchanged.

## Review remediation clarification (2026-11-09)

Operator-authorized run 2026-11-09-81798e61 tightens this design without accepting the Proposed ADR. A PRESENT value on a MULTI MEMBER must canonicalize to its immutable member key; mismatches reject `MEMBER_VALUE_MISMATCH` before any write. Decimal input and canonical output share the schema's 64-character total bound, with length checked before exponent expansion and canonical reload idempotent. Follow-up migration0013 requires the complete legacy/v1 identity shape to be TRUE and refuses existing malformed rows without repair. Scope-dependent reads authorize the exact privately loaded payload and its evidence scope in one current-authority unit of work before returning. The feature assembly plan records ownership and required regression proofs.

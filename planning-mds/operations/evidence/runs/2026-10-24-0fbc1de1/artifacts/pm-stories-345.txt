## Story Header

**Story ID:** F0005-S0003

**Feature:** F0005 — One-time document ingestion

**Title:** Reinterpret saved JSON and map evidence

**Priority:** High

**Phase:** MVP — v0.1A

**Status:** In Progress

## User Story

**As a** document intelligence engineer

**I want** live interpretations over saved native content with evidence grounded in actual source regions

**So that** a profile change enriches knowledge without reparsing or inventing locations.

## Context & Background

Implements the [PRD](PRD.md) under proposed [ADR-0060](../../architecture/decisions/ADR-0060-docling-graph-document-pipeline-orchestration.md) and accepted ADR-0058. Delivered 2026-09-22: evidence mapper v2, multi-region grounding and recorded-response dense extraction. This plan proves the same behavior with live model output on the qualification corpus.

## Acceptance Criteria

- [ ] **F0005-S0003-AC1:** Given each published corpus bundle after a worker restart, when `gl-limits-a` and `gl-limits-b` run through the live dense contract, then saved DoclingDocument JSON is the only input, converter/OCR entry points are instrumented and called zero times, bundle hashes are unchanged, and each run records distinct template, schema, chunking, model and tokenizer identities.
- [ ] **F0005-S0003-AC2:** Given live output for limits, dates and the named insured, when evidence is resolved, then every resolved selector's source text supports its value (Unicode offsets and table cells checked against the bundle), repeated or ambiguous values stay unresolved, and multi-region values need complete character coverage.
- [ ] **F0005-S0003-AC3:** Given Graph chunks, nodes and properties, when the adapter builds InterpretationResult, then the provenance ledger and native item references are retained as run outputs; graph IDs and local merges never become enterprise identity or canonical facts.
- [ ] **F0005-S0003-AC4:** Given output containing relationships or entity types without a downstream mapping, when it is imported, then the import fails closed with an explicit unsupported-output reason and no partial assertions.
- [ ] **F0005-S0003-AC5:** Given any model call (skeleton, fill, repair or reconciliation), when it is scheduled, then input + schema + output reservations measured with the serving tokenizer fit the 4,096-token context; an oversized request fails before sending.
- [ ] **F0005-S0003-AC6:** Given a selected-block or targeted request, when interpretation begins, then it fails explicitly as unsupported rather than broadening to the full document; F0032 owns targeted evolution.
- [ ] **F0005-S0003-AC7:** Given a job, artifact or run state change, when the operation succeeds or fails, then an audit event records actor and job identity, correlation and attempt IDs, artifact/run references, outcome and timestamp, without secrets or source text.

**Edge Cases & Error Scenarios:** Value printed differently from the expectation (e.g. `$1M`) → reported as an accuracy miss, not normalized into a match. Model returns a value absent from the document → unresolved evidence and an accuracy miss, never a fabricated span. A chunk boundary splitting a value → multi-region resolution or unresolved, never truncation.

## Interaction Contract

No UI. Entry points: worker interpretation stage and the importer; review items appear in the existing Review Panel unchanged.

| Surface / Entry Point | User Action | Editable State | Save / Mutation Result | Reload / Persistence Evidence | Roles / Status Constraints |
|---|---|---|---|---|---|
| Interpretation over a published bundle → importer | Run a profile against an artifact | New run only; bundle and prior runs immutable | Run outputs plus assertions, evidence and review items in one transaction, or explicit failure | Reload run, assertions and evidence selectors; recheck selectors against bundle text | ServicePrincipal `interpret` grant; canonical acceptance excluded |

**Validation and audit:** unresolved evidence enters provenance review per ADR-0058; nothing is committed canonically.

## Data Requirements

Run identity and configuration hashes, chunk inventory, provenance ledger, per-call token reservations and usage, evidence precision per value.

## Role-Based Visibility

Run outputs require current `interpret` authorization in the source's tenant/KB, rechecked after restart. Model context contains chunk text only.

## Non-Functional Expectations

- Every call's reservation is checked before sending; budgets cover repairs.
- Per-document-profile latency is reported for S0004's threshold.

## Dependencies

S0001/S0002; fixed proof profiles; ADR-0040/ADR-0058; F0015/F0016 for production profiles and run lifecycle.

## Out of Scope

Relationship semantics, new profiles, targeted evolution, canonical commits.

## Questions & Assumptions

Two fixed profiles remain sufficient for qualification; F0015 compiles production templates against the qualified adapter.

## Definition of Done

- [ ] Every acceptance criterion has observed live-model evidence.
- [ ] Applicable runtime tests, authorization checks and contract validation pass.
- [ ] STATUS, compatibility evidence and trackers describe the actual implementation.
- [ ] Required reviewer verdicts are recorded in STATUS; planning checks are not runtime proof.

## Story Header

**Story ID:** F0005-S0004

**Feature:** F0005 — One-time document ingestion

**Title:** Evaluate and activate the proven pipeline

**Priority:** High

**Phase:** MVP — v0.1A

**Status:** In Progress

## User Story

**As a** platform owner

**I want** a measured direct-versus-Graph comparison against agreed thresholds, followed by activation or rejection

**So that** Graph replaces the direct client only on evidence, and either outcome is recorded and reversible.

## Context & Background

Implements the [PRD](PRD.md) under proposed [ADR-0060](../../architecture/decisions/ADR-0060-docling-graph-document-pipeline-orchestration.md). Delivered 2026-09-22: a recorded-response [synthetic comparison](synthetic-comparison.json), which is orchestration proof, not model quality. This plan adds the live corpus comparison, reviewer verdicts and the activation decision.

## Acceptance Criteria

- [ ] **F0005-S0004-AC1:** Given the qualification corpus (at least 12 synthetic documents: 6 native, 4 scanned, 2 mixed-page), when it is committed, then every expected value and evidence location was authored from the document source by a role that does not run or review the extraction, and the corpus and expectation hashes are recorded before the first measured run.
- [ ] **F0005-S0004-AC2:** Given the direct baseline and Graph dense under recorded configurations (pins, model and tokenizer revision, chunking, budgets), when both profiles run over the full corpus, then the report records per-case and aggregate schema validity, field accuracy, abstention, fabricated evidence, evidence resolution, calls, serving-tokenizer tokens, p95 latency and review items per document.
- [ ] **F0005-S0004-AC3:** Given the report, when it is compared with the PRD thresholds, then each threshold is marked met or missed with its measured value; a missed threshold blocks activation and is never re-run with relaxed budgets to pass.
- [ ] **F0005-S0004-AC4:** Given S0001–S0003 and S0005 evidence plus the report, when QA, Architect and Security review them, then each records a verdict with evidence references in STATUS, and the operator records acceptance or rejection.
- [ ] **F0005-S0004-AC5:** Given all thresholds met, every verdict passing and operator acceptance, when activation runs, then ADR-0060 becomes Accepted, the worker default extraction contract becomes Graph dense through committed non-secret configuration, the v2 writer is enabled per S0005, and the dependency matrix, build/run metadata and C4 runtime description are updated together.
- [ ] **F0005-S0004-AC6:** Given an activated configuration, when the rollback setting selects the direct baseline, then new runs use the direct client with its own identity, existing artifacts and runs stay readable and unchanged, and no run mixes engines.
- [ ] **F0005-S0004-AC7:** Given any threshold miss, failing verdict or operator rejection, when the feature closes, then the direct client stays default, the v2 writer stays disabled, ADR-0060 records the failed gates (Proposed or Rejected per operator), and no partial activation remains.
- [ ] **F0005-S0004-AC8:** Given a job, artifact, run or activation state change, when the operation succeeds or fails, then an audit event records actor and job identity, correlation and attempt IDs, artifact/run references, outcome and timestamp, without secrets or source text.

**Edge Cases & Error Scenarios:** Live model unavailable during measurement → the run is void and repeated in full, never partially merged. Baseline worse than Graph on every metric → still reported; the baseline remains the rollback path. Reviewer finds an expectation error → the corrected expectation is re-hashed and both engines are re-measured.

## Interaction Contract

No UI. Entry points: the comparison harness, the committed configuration file and the ADR/STATUS records.

| Surface / Entry Point | User Action | Editable State | Save / Mutation Result | Reload / Persistence Evidence | Roles / Status Constraints |
|---|---|---|---|---|---|
| Comparison harness → report | Run both engines over the corpus | Report immutable once recorded; a re-run creates a new report | Hashed report with per-case rows | Re-run reproduction command; compare corpus and configuration hashes | QA owns corpus; AI engineer runs; reviewers do not author expectations |
| Committed configuration | Activate or roll back | Default extraction contract and `content.v2_writer_enabled` | Next job uses the selected engine and writer | Restart worker; submit a document; inspect run and manifest identity | Activation only after AC4 acceptance |

**Validation and audit:** activation and rollback are recorded in STATUS and the feature evidence package with the operator's decision.

## Data Requirements

Corpus manifest and hashes, expectation files, run configurations, per-case results, aggregate metrics, verdicts, activation decision and configuration diff.

## Role-Based Visibility

Corpus and reports are synthetic and repository-committed; measured runs execute under the ServicePrincipal's current authorization like any job, and activation needs no new permission; reports exclude secrets and serving credentials.

## Non-Functional Expectations

Thresholds as listed in the PRD. Measurement uses one worker replica and the model semaphore at 1.

## Dependencies

S0001–S0003, S0005; agent-role QA, Architect and Security reviewers; operator acceptance; F0026 reuses the cases.

## Out of Scope

Production host activation, licensed or frozen-holdout corpora, retiring the direct client code (it stays as the rollback path).

## Questions & Assumptions

Thresholds are the operator-approved PRD defaults. Graph direct is reported for completeness but is not an activation candidate.

## Definition of Done

- [ ] Every acceptance criterion has observed evidence.
- [ ] Applicable runtime tests, authorization checks and contract validation pass.
- [ ] STATUS, ADR-0060, dependency matrix and trackers describe the actual outcome.
- [ ] Required reviewer verdicts and the operator decision are recorded; planning checks are not runtime proof.

## Story Header

**Story ID:** F0005-S0005

**Feature:** F0005 — One-time document ingestion

**Title:** Qualify text origin and enable v2 publication

**Priority:** High

**Phase:** MVP — v0.1A

**Status:** Not Started

## User Story

**As a** document intelligence engineer

**I want** every published block to carry an observed text origin and exact OCR provenance before the v2 writer is switched on

**So that** downstream admission and review never rely on inferred origins or unidentified OCR models.

## Context & Background

F0004 delivered v2 content contracts, per-item origin projection, the `content.v2_writer_enabled` switch (default `false`) and the per-document v1 fallback, and its Step 1a spike passed on three synthetic fixtures. F0004 closeout assigned F0005 two obligations before broader activation: fixed Docling/hook qualification and exact OCR model-asset provenance. This story also satisfies the 2026-09-25 A-4 activation prerequisite under ADR-0065. See the [PRD](PRD.md).

## Acceptance Criteria

- [ ] **F0005-S0005-AC1:** Given every qualification-corpus document converted live, when per-item origin is projected, then each native text item is `STATED` with its observed producer, each OCR item is `OCR` with engine name/version, and items that cannot be attributed return `ORIGIN_UNAVAILABLE`; no origin is derived from page OCR counts.
- [ ] **F0005-S0005-AC2:** Given OCR ran, when the bundle is published, then the OCR model assets used are identified by name, revision and file SHA-256 read from the installed asset files; an unidentifiable asset blocks v2 publication for that document instead of recording a guessed identity.
- [ ] **F0005-S0005-AC3:** Given a document with any `ORIGIN_UNAVAILABLE` item and the v2 writer enabled, when it is published, then it falls back to a v1 bundle with `writer_fallback_reason=ORIGIN_UNAVAILABLE` audited, and the per-corpus fallback rate is reported.
- [ ] **F0005-S0005-AC4:** Given v2 bundles from the corpus, when every existing consumer reads them (authorized content reader, evidence resolver, Graph adapter saved-JSON path, importer, restore drill), then they pass with unchanged behavior; v1 bundles stay readable.
- [ ] **F0005-S0005-AC5:** Given AC1–AC4 pass and S0004 activation is accepted, when `content.v2_writer_enabled` is set to `true` in committed configuration, then new sources publish v2 bundles and existing artifacts are not rewritten.
- [ ] **F0005-S0005-AC6:** Given a job, artifact or run state change, when the operation succeeds or fails, then an audit event records actor and job identity, correlation and attempt IDs, artifact/run references, outcome and timestamp, without secrets or source text.

**Edge Cases & Error Scenarios:** OCR assets present but altered after install → digest mismatch blocks v2 publication. Mixed page with an image region OCR skipped → that region's items `ORIGIN_UNAVAILABLE`, document falls back to v1. Docling upgrade → origin hook re-qualified before the switch stays on.

## Interaction Contract

No UI. Entry points: the publication boundary and the committed `config/local.yaml` switch.

| Surface / Entry Point | User Action | Editable State | Save / Mutation Result | Reload / Persistence Evidence | Roles / Status Constraints |
|---|---|---|---|---|---|
| Publication boundary with v2 writer | Publish a converted document | New bundle only | v2 bundle with per-item origins and OCR asset identity, or audited v1 fallback | Reload through the v2 verifier; check manifest version, origins and asset digests | ServicePrincipal `ingest`; switch flipped only after S0004 acceptance |

**Validation and audit:** the switch change is recorded with the activation decision; fallbacks are audited per document.

## Data Requirements

Per-item origin and producer, OCR engine name/version, OCR asset name/revision/SHA-256, fallback reason and rate, manifest contract version.

## Role-Based Visibility

Unchanged from F0004: origin metadata follows artifact access.

## Non-Functional Expectations

Origin projection adds no model call and no second conversion.

## Dependencies

F0004 v2 contracts, projection and fallback; S0001 live conversion; S0004 activation decision; ADR-0065 (Proposed; only its storage carry-in applies).

## Out of Scope

`TRANSCRIBED` and `DESCRIBED` producers, new OCR engines, rewriting legacy bundles, assertion admission behavior (F0006).

## Questions & Assumptions

The v2 switch flips only together with S0004 activation; on rejection it stays `false`.

## Definition of Done

- [ ] Every acceptance criterion has observed evidence on live conversions.
- [ ] Applicable runtime tests, authorization checks and contract validation pass.
- [ ] STATUS, compatibility evidence and trackers describe the actual implementation.
- [ ] Required reviewer verdicts are recorded in STATUS; planning checks are not runtime proof.

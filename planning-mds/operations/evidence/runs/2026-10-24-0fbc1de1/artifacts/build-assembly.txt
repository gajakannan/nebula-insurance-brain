    80	## Step 3 — Text origin and OCR asset provenance (S0005)
    81	
    82	`item_provenance.py` currently records `ProducerIdentity(engine_class, version("rapidocr"), None, None)` for RapidOCR items, with the model fields null.
    83	
    84	- Resolve the RapidOCR detection, recognition and classification model files actually loaded by the configured pipeline (read from the engine instance's configured model paths, not from defaults or documentation). Hash each file's bytes at conversion time.
    85	- Write the result into slots that already exist and are always written empty today:
    86	  - The v2 manifest's `execution.model_artifact_digests` (array of strings), as `<asset-name>@<revision>:sha256:<hex>`; `content_workflow.py` and `bundle_writer.py` currently write `[]`.
    87	  - The per-item `ProducerIdentity.model` and `model_version` fields, which are currently `None` for OCR items.
    88	- No schema change is needed. If the contract cannot express what is observed, stop and return to the architect.
    89	- An asset path that cannot be resolved, or a digest that differs from the value recorded at preflight, makes the document `ORIGIN_UNAVAILABLE` for its OCR items, so the per-document v1 fallback applies (S0005-AC2/AC3). No guessed identity is written.

    92	## Step 4 — Failure injection (S0002)
    93	
    94	Test-only composition, never shipped in the production worker path:
    95	
    96	- **Model fault proxy** `neuron/tests/support/fault_proxy.py`: an HTTP proxy between the worker and vLLM with modes `pass`, `stopped` (connection refused), `timeout` (hold beyond the client timeout), `http_5xx`, `malformed_json` and `schema_invalid` (valid JSON violating the template). Mode is selected per request number so a retry can succeed.
    97	- **Storage fault** wrapper over the filesystem object store that raises on the Nth write or before the manifest marker.
    98	- **Process kills:** extend `test_document_process_recovery.py` to run with the live model through the proxy in `pass` mode at the four kill points (after bundle publication, after result publication, mid-import, after import commit).
    99	- **Assertions:** conversion and OCR counters are instrumented at the converter and RapidOCR entry points (not self-reported). Database row counts prove one accepted artifact, one run per profile and one assertion/evidence/review set. Reason codes are distinct per fault mode.
   100	- **Concurrency (AC4):** submit 5 jobs with two worker processes on one host; assert via proxy request timestamps that in-flight model requests never exceed the configured limit (default 1), and that cancellation leaves at most one in-flight request and schedules none after it.
   101	- **Authorization (AC5):** revoke the ServicePrincipal grant or deactivate the principal between attempts; the next boundary denies and audits, and the job does not continue.
   102	- **Temporary exports (AC6):** after completed, failed and cancelled runs, assert the attempt's temporary directory is removed and retained run outputs carry the source's tenant/KB scope. Retention period and deletion follow the source (F0004); F0005 adds no retention policy.

   105	
   106	Extend `test_graph_live_inference.py` (opt-in) to run both profiles with `extraction_contract="dense"` over every corpus bundle after a worker restart, with converter/OCR entry points patched to raise.

   113	## Step 6 — Pipeline selection and rollback path
   114	
   115	Add a committed, non-secret section to `config/local.yaml`, loaded beside `ContentWriterConfig`:
   116	
   117	```yaml
   118	extraction:
   119	  # graph-direct (current opt-in behavior) | graph-dense | direct-baseline
   120	  pipeline: graph-direct
   121	```
   122	
   123	- **Job pinning:** the selected pipeline is written into the job `payload` at submission, as the profile and schema hash already are, and is covered by the idempotency check. Retries and recovery use the pinned value. A configuration change affects new submissions only, so no run mixes engines (S0004-AC6). No migration is needed: `payload` is JSON.
   124	- **Run identity:** the interpretation run records the pipeline value, Graph revision and contract, or the direct adapter's identity.
   125	- **Direct baseline in the worker:** wrap `OpenAICompatibleExtractionAdapter` behind the same interpretation interface as `GraphInterpretationService`, with the same `VllmGraphClient` budget and semaphore policy, evidence mapper and importer. It must pass the Step 4 recovery suite and the Step 5 evidence checks before it can serve as a rollback.
   126	- An unknown value fails worker startup with a configuration error; there is no environment-variable override.

   128	## Step 7 — Comparison, review and decision (S0004, S0005-AC5)
   129	
   130	**Harness:** `neuron/benchmarks/f0005_qualification.py --corpus neuron/fixtures/qualification --pipelines direct-baseline graph-dense graph-direct --output <run>/artifacts/qualification/report.json`. It reuses the scoring of `docling_graph_comparison.py`, runs through the worker composition against live vLLM, and records configuration hashes, pins, corpus and expectation hashes, and per-case rows. Graph direct is reported but is not a candidate.
   131	
   132	**Metrics,** exactly as the PRD defines them:
   133	
   134	- Accuracy: normalized exact match. Normalization is limited to whitespace collapse and Unicode NFC; no currency or date reformatting.
   135	- Abstention: computed over expected-null fields.
   136	- Fabricated evidence: resolved selectors whose re-read text fails the value comparison.
   137	- Evidence resolution: exact span or cell over correct values.
   138	- Latency: wall time from interpretation start to result publication per document-profile; p95 by nearest rank.
   139	- Review workload: review items created per document.
   140	
   141	**Void runs:** if the provider fails mid-measurement, the whole report is void and rerun. Reports are immutable; reruns get a new file.
   142	
   143	**Decision sequence:**
   144	
   145	1. Mark each threshold met or missed in `report-summary.md`.
   146	2. The three independent review sessions write verdicts with evidence references into STATUS's append-only provenance table.
   147	3. The operator records acceptance or rejection.
   148	4. **On acceptance:** in one change, set `extraction.pipeline: graph-dense` and `content.v2_writer_enabled: true`; mark ADR-0060 Accepted with the evidence links; update `docker/DEPENDENCY-MATRIX.md`, build/run metadata, the C4 container description and BLUEPRINT §2.1/§4.8. Then submit one new corpus document and verify the pipeline, run identity and v2 manifest after a restart. Rollback is verified by switching `extraction.pipeline: direct-baseline`, submitting again, and confirming earlier artifacts and runs are unchanged.
   149	5. **On rejection:** both settings stay as they are. ADR-0060 records the failed gates and stays Proposed, or becomes Rejected if the operator says so. The direct-baseline worker path remains available as built.

   151	## Contracts, data and authorization
   152	
   153	- No new endpoint, schema file, role or permission. Existing `ServicePrincipal` `ingest`/`interpret` grants cover all qualification jobs; Casbin policy is unchanged.
   154	- S0005 fills existing, currently empty fields of `schema:content-artifact-manifest-v2`; no shape change.
   155	- **Failure reasons (migration 0009, expand-only).** `document_job_event` records only `event` (state); `DocumentJobQueue.retry()` has no reason. Add a nullable `reason VARCHAR(64)` column with a CHECK constraint over this enumeration:
   156	  - `model_unavailable`, `model_timeout`, `model_http_error`, `model_malformed_output`, `model_schema_invalid`
   157	  - `storage_write_failed`, `conversion_failed`, `conversion_timeout`, `stage_guard_mismatch`
   158	  - `unsupported_targeting`, `unsupported_output`, `authorization_denied`, `cancelled`
   159	
   160	  `retry()` and the terminal-failure path take a required reason. Existing rows keep `NULL`, with no backfill and no edit to migrations 0001–0008. This is F0003's expand-only discipline; the restore drill covers the new column.
   161	- Audit: authorization decisions stay in `audit_event` with policy version. Job state changes are the append-only `document_job_event` rows, each carrying job, generation (attempt), event, the new reason and time. Correlation and artifact/run references come from the job row and outbox.
   162	- Data egress: model requests carry chunk text only (ADR-0055). Diagnostics and reports carry hashes, usage and reason codes, never prompts, responses, source text or keys.

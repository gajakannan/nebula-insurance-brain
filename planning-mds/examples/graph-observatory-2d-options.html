    Reviewer's recommendation, for you to overrule
    
  
      
    
    • Use A as the Observatory canvas. It keeps the reference look (clusters, crawler focus, tentacles, tags, HUD) without a 3D stack. The reference video is mostly a 2D field with camera pan and zoom.
      • 
    
    • Use B for the Learning Observatory. One lane per knowledge layer makes "proposed, not committed" and "zero canonical change" visible.
      • 
    
    • Use C as the accessible and inspection view, built on F0045's Cytoscape explorer rather than a new graph library.
      • 
    
    • If you keep 3D, use E, not D. E puts height on the knowledge layer, which meets ADR-0072 §5's rule that depth must encode something recorded. D's depth encodes nothing; it stays here only as the contrast.
      • 
    
    • With E, the set would be: E as the Observatory canvas where WebGL is available, A as its fallback, B for learning runs, and C as the accessible view. The cost is a GPU rendering stack in the frontend (F0021 dependency policy) and a second accessibility path.
      • 
  
    
  
    What the fixture shows on purpose
    
  
      
    
    • Retrieval candidates are only "observed" until the answer-basis event classifies them. Nothing is "used" because it was visited.
      • 
    
    • The superseded $2M limit was traversed but is "considered, not used". The declarations page is used only for the caveat.
      • 
    
    • The answer composer is an explicit instrumentation gap. Its internal steps are not drawn.
      • 
    
    • The learning run ends with zero canonical changes, one unresolved conflict, one ontology proposal and one statement with no fit.
      • 
    
    • Ambient points show permission-safe aggregate density. They are not entities and are never touched by the crawler.
